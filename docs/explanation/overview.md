# 定位：为什么不是一个「多平台机器人框架」

> **状态**：已决议
> **日期**：2026-10-31
> **读者**：第一次接触本项目、要判断「这东西和已有的有什么不同」的人
> **上游材料**：[生态与协议路线](ecosystem.md)、[外部依据](../reference/sources.md)
> **口径**：定位与取舍，不含实现细节

## 一句话

**让每个聊天平台变成一台「MCP Server」，DSH 做它的 client。**

| 平台侧的东西 | 在我们这里是什么 | MCP 语义 |
|---|---|---|
| 平台消息 | 触发一轮对话 | sampling 请求（平台找 AI 生成回复） |
| 平台动作（点赞、禁言、踢人） | 自动生成的 AI 工具 | tools |
| 渠道人格（每平台 / 每群的忌讳与语气） | agent 作用域提示词 | prompts |
| 频道上下文（群历史、成员） | 上下文资源 | resources |
| 平台事件（入群、撤回） | 事件流 | notifications |
| 要人类拍板 | 审批闸门 | elicitation |

用户原始构想「DSH 做后端 + 多种协议接入不同聊天端」的完整形态，且**不需要额外代码**：驱动声明动作目录，内核自动翻译成 AI 可调用的工具 —— 没有词表的能力由驱动自带的 MCP server 提供。

## 与已有方案的区别

- **不是「一个机器人接了很多平台」，是「一个人同时活在很多地方」。** 平台差异收敛成一份*动作目录*，人格差异收敛成*场所*与*分层记忆*。
- **驱动声明动作，工具自动生成。** 一份 `ActionDescriptor` 同时决定模型能做什么、能不能自主做、要不要人点头；模型不认识的平台能力走 MCP 工具，同样进视野。
- **权限跟着消息走。** 每条入站消息先判发起者、得到本回合的角色，再按角色查规则；模型说了什么永远不构成授权。
- **记忆是 git 仓库。** 可回滚、可分叉、可夜间整理（做梦）、可连同人格一起搬到新机器。
