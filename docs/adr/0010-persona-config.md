# ADR-0010：人格的配置面

> **状态**：`accepted`
> **日期**：2026-11-02
> **落地阶段**：P1
> **上游材料**：[设置页面板](0009-settings-panel.md)、[人格引擎契约](../reference/contracts-persona.md)、[DSH 接缝](../reference/dsh-seams.md)

## 背景

设置页的连接分区已经能改了。剩下两个分区（模型、场所）无处可写：驱动的 config 只有连接字段，人格在这一层还没有配置面。

加字段之前要先回答两个问题：**什么东西算设置**，以及**它以什么形式出现**。这两个问题答错，后面每加一个功能就要重新吵一次。

## 决策

### 一个设置 = 一个无法从别处推出的判断

人格身上能被人判断的只有四件事，其余全是派生：

| 可设置 | 为什么无法推出 |
|---|---|
| `personaId` | 它是谁，决定人设、记忆、产物落在哪个目录 |
| `provider` / `model` / `reasoningEffort` | 用哪个脑子。成本与能力是人的判断，不是代码能算的 |
| `mutedVenues` | 在哪些场所安静。这是授权，不是事实 |
| —— | 数据根不是字段：由 `DSH_HOME` 推出 |

| 派生 | 怎么推 |
|---|---|
| 会话 id | `shixu-<venueKey>` |
| 会话 cwd | 人格根 |
| 记忆与产物路径 | 人格根下的固定子目录 |
| 连接方向、地址、令牌 | 驱动的事，不是人格的事 |

判断标准只有一句：**这个值能不能从别处算出来？** 能算出来的不进配置，否则同一件事就有两个家。

### 场所清单是例外，不是白名单

默认**哪里都在场**。`mutedVenues` 里列的是「别在这里说话」。

理由：一个号被拉进哪个群是人的决定，人格在被拉进去的地方说话才自然。反过来做成白名单，新装好的第一件事是一句话都不回，使用者只会以为坏了；而且「让它能说话」要从每个群办一次手续。

### 所有场所共用一个 cwd

会话的 cwd 是 `$DSH_HOME/persona/<personaId>`，不是每个场所以一份。

工作区记录按 cwd 归组：按场所分 cwd，10 个群就是侧栏里 10 个项目，很快没人认得出这是一个人格。场所自己的 `venues/<venueId>/scratch` 是产物约定，不是会话 cwd。

### 形式：按值的形状选

| 值的形状 | 形态 | 例子 |
|---|---|---|
| 标量 | 原生表单字段 | `provider`、`model` |
| 例外清单 | 一组字符串，可增删 | `mutedVenues` |
| 运行事实 | 只读，不能编辑 | 当前在线的群、连接状态 |
| 派生事实 | 不出现 | cwd、sessionId |

原生表单只表达「值」，所以清单与运行事实只能自定义；反过来，能用一个字段说清的事不去写组件。

## 被否决的替代

| 替代 | 否决理由 |
|---|---|
| 场所白名单（默认全静默） | 新装好一个群都不回，被当成坏了；把「能说话」变成每个群一次的仪式 |
| 每场所一个 cwd | 工作区按 cwd 归组，10 个群 = 10 个侧栏项目，人格在界面上散架 |
| `venues` 做成 `{ venue, enabled }` 数组 | 数组里的对象在 schemastery 声明发射时引入 cosmokit 的 `Dict` 名字，产物类型不可移植；一组字符串解决同一个问题 |
| 模型 / 场所放进驱动行 | 驱动是协议适配。人格配置放进去，等于每个协议各带一份人设 |
| `personaId` 做成面板字段 | 现在只有一个合法值，露出来只是让人多填一格 |

## 后果

- 模型与场所的改动**下一次唤醒就生效**（volatile 字段按引用读）；连接的地址与端口仍然需要重启。
- 面板要读第二个命名空间（binding 行），也就是第二份表单。
- 老会话留在 `_no-cwd` 里不搬家：`resume` 没有 cwd 参数，会话的 cwd 建好之后不再变。

## 未决

- 角色矩阵（每个场所谁能指挥它）v2 再进面板。
- 多个人格：`personaId` 字段已经在，界面里不露。
