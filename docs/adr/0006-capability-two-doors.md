# ADR-0006：能力只有两条门，未抽象的东西走 MCP

> **状态**：`accepted`
> **日期**：2026-11-01
> **落地阶段**：P2
> **上游材料**：[渠道内核契约](../reference/contracts-channel.md)、[判据与默认值](../reference/policies.md)

## 背景

统一抽象只能有词表里已经存在的概念。平台每年长出新东西 —— 戳一戳、群文件、语音房、频道分区、线程、Sticker —— 把它们逐个塞进 `UnifiedEvent` / `ActionDescriptor` / `Capabilities`，等于让抽象永远追着平台跑；而且每加一个，所有驱动的编译面都动一次。

但内核又必须知道「这个动作能不能撤、要不要人点头」，否则[红线 5](../reference/policies.md#红线)落不了地。

## 决策

**能力有两条门，都是原始设计。没有「逃生舱」这回事，也不叫降级。**

| 门 | 谁定义 | 怎么进模型视野 | 适合什么 |
|---|---|---|---|
| A 声明式 | `ActionDescriptor` + `Capabilities` | 内核把动作目录翻成 `{platform}_{action}` 工具 | 说得出后果、内核能据此决定放行还是问人的能力 |
| B MCP | 驱动自带的 MCP server | `mcp__<serverName>__<tool>`，挂在场所的 agent 上 | 我们连它是什么都还没概念化的能力 |

**门 B 不进契约。** `ChannelDriver` 里没有 MCP 字段：驱动自己把 server 挂到 agent 上，内核不看它的配置、不解析它的工具。契约里多一个字段，就是把「我们以为的平台差异」又写死一次。

选哪条门是驱动作者的判断。**内核不判断「这个平台该有哪些能力」，只判断「这个动作危险不危险」** —— 一旦它开始维护平台能力清单，抽象就又回到了「把差异全建模」的老路。

## 为什么门 B 不能自带风险等级

初稿在 `ChannelDriver.mcpServers` 上留了一个 `risk` 字段，由驱动声明。这是错的，两条理由：

1. **能写出 risk，就说明已经抽象完了。** `risk` 是「这个动作做什么、后果多大、能不能撤」的结论；能得出这个结论，这个词条就已经被概念化，那它就该进动作目录。留在门 B 还带分级，等于把门 A 的判断标准搬过去，同时免掉门 A 的义务（参数 schema、命名、可逆性）。
2. **由驱动负责，它就会走捷径。** 手上有两扇门：一扇要写 `ActionDescriptor`，另一扇只要三行 YAML —— 门 B 会变成停车场，而不是过渡通道。

所以门 B **没有任何分级、豁免或白名单**。

## 门 B 的代价：它不能自己动手

内核不判断门 B 的工具危不危险 —— 它没这个能力，硬判就是假装知道。它只认一件事：**名字以 `mcp__` 开头的工具，来源不在我们的词表里**。

由[红线 5](../reference/policies.md#红线)：不可逆动作不产生凭据 ⇒ 不允许自主执行。门 B 的动作既没有回执也没有 undo（我们不知道它做了什么），所以它天然落在「不能自主执行」那一侧。这不是惩罚，是它自己没资格主张自主。

这条同时就是毕业的推力：**想少打扰人，唯一的路是抽象成门 A。** 门 B 用得越频繁，人越烦，抽象的动力越强；用得少，说明它本来就不值得抽象。不需要再立一条「定期清理」的规矩 —— 价格本身会清场。

## 被否决的替代

| 替代 | 否决理由 |
|---|---|
| 门 B 带 `risk` 并由驱动声明 | 能写出 risk 的已经该进 A；留给 B 只会制造停车场 |
| 持续扩展统一模型 | 抽象永远追不上平台，且每扩一次所有驱动的编译面都动 |
| 用 `raw` / `native` 当能力出口 | 那一对只解决消息**表达**的透传，解决不了**动作** |
| 所有平台能力都走 MCP | 丢掉三样内核存在的理由：风险分级、降级留痕、跨平台一致的命名与审批闭合 |

## 影响

1. **契约零改动**：`ChannelDriver` 里没有 MCP 字段，门 B 是驱动与 `dsh-mcp-client` 之间的事。
2. 内核的门 B 闸门按 `mcp__` 前缀，不按来源登记。代价：任何自称 `mcp__` 的工具都被同等对待 —— 可以接受，因为它本来就属于「我们不知道它是什么」那一类。
3. DSH 原生支持 agent 作用域的 MCP 实例（`dsh-mcp-client` 的 `serverName` 按注册作用域隔离，同一 `serverName` 可在不同 agent 复用），所以「1 场所 = 1 agent」天然不串味。stdio 传输等于每场所一个子进程，驱动应优先提供 `streamable-http`。
4. 挂载缝与人工确认粒度未定，见[待拍板](README.md#待拍板)。
