# ADR-0001：权限判据改用「可逆性 × 影响半径」

> **状态**：`accepted`
> **日期**：2026-10-30
> **落地阶段**：P0
> **上游材料**：[权限与身份](../explanation/permission-identity.md)

## 背景

给自主回合划权限边界时，最直觉的分法是按动作的「破坏性」三级：读 / 写 / 破坏。生态里的项目基本都这么做，代码里也最容易写。

这个分法在我们这里会给出**刚好相反**的结论：

| 动作 | 「破坏性」分级 | 实际风险 |
|---|---|---|
| 发布一个网页到公网 | 破坏性（对外） | 低 —— 能一键下线 |
| 删一条群消息 | 写 | 高 —— 不可恢复 |
| 封人 / 踢人 | 破坏性 | 低 —— 能解封 |

按破坏性分级会导致：人格想发个页面必须先问人，而删消息却能直接删。

## 决策

按**可逆性** × **影响半径** 两维分级：

- 可逆 = 能撤回、能恢复（有快照、有 `undo`）；
- 影响半径 = 只影响本场所，还是影响对外 / 他人 / 主人的信用与金钱。

只有「不可逆 + 高影响」在自主回合禁止；其余都允许，代价是必须留动作凭据可一键回滚。

## 被否决的替代

- **按破坏性三级（read / write / destructive）**：给出的结论与实际风险相反，见上表。
- **全部要审批**：做不到拟人，且群里每个人都被打扰。
- **按金额阈值**：只覆盖「花钱」一项，漏掉「以你名义承诺」这类无金额但高影响的动作。

## 影响

- 每个 `ActionDescriptor` 必须声明 `risk`，动作目录要能标注 `reversible` 与快照能力；
- 内核必须自动采集动作前快照（成员 id / 发布 URL / message id），否则「可撤回」是空话；
- 不可逆动作不产生凭据 ⇒ 自主时直接拒绝，而不是「记录下来再问」。
