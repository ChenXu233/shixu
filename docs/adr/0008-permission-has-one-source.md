# ADR-0008：权限只有一份真相

> **状态**：`accepted`
> **日期**：2026-11-01
> **落地阶段**：P0
> **上游材料**：[身份与权限](../reference/contracts-persona.md#身份与权限)、[ADR-0007](0007-rbac-carries-authorization-and-risk.md)

## 背景

[ADR-0007](0007-rbac-carries-authorization-and-risk.md) 定了「矩阵决定放行 / 问人 / 拒绝」。落地时它长出了三层其实在说同一件事的东西：身份凭据里一套 `scopes`、矩阵里一套规则、外面再包一个 `decide()` 函数。

三层都要回答「谁能做什么」。任何一处漂移，结果不是静默放权就是静默拒绝 —— 而两边的测试看上去都是绿的。

## 决策

**砍到三个名词。**

| 名词 | 是什么 |
|---|---|
| `TurnActor` | 这个回合是谁在说话：`subject` + `role` + `venueId` |
| `PermissionRule` | 一个角色对一个工具名的一个决定 |
| `tools/pre-execute` 监听 | 判定发生的地方，返回 `allow` / `ask` / `deny` |

判定三步：**从后往前**第一条命中的规则胜出 → 一条都没命中用工具的原生默认 → 都没有就 `deny`。

不是「取最严」：`{ match: '*', decision: 'deny' }` 打底之后，`allow` 会永远输给它，用户只能拿到默认拒绝。角色存在的目的就是从默认里放开几条，顺序必须能表达覆盖。

## 砍掉了什么，为什么

| 砍掉 | 理由 |
|---|---|
| `decide()` | 它要做的事就是那个钩子要做的事，而钩子的返回形状本来就是 `allow` / `ask` / `deny`。多起一个名字，就多一份要同步的语义 |
| `scopes` | 工具名已经表达了。多一层分类，迟早和工具名漂移；真要粗粒度，一条 `{ match: 'qq_*' }` 就够了 |
| `mac` / `epoch` / `expiresAt` | 进程内没有对手：能改这三个字段的代码，本来也能改任何东西。签名只在跨进程时才有意义 |

## 被否决的替代

| 替代 | 否决理由 |
|---|---|
| 保留 `decide()` 作为「契约函数」 | 契约的价值是拦住第二套语义，而这里已经有一套（钩子）。多一层包装不增加约束，只增加要同步的地方 |
| 保留 `scopes` 做粗粒度开关 | 通配规则已经能做；留着就是第二个真相 |
| 现在就上 HMAC 与 `epoch` | 没有对手的安全机制不是安全，是延迟 |

## 影响

- **红线 3 的判据改了**：从「必须验签 token」改成「判定只读服务端状态」。意图不变（不信模型说的话），机制按现有边界写。
- **改动权限立即生效**：下一回合重新查表。没有旧凭据需要作废 —— 也比「回合内锁定旧权限」更安全，因为撤销会立刻被看到。
- 等跨进程的线缆协议出现（[待拍板](README.md#待拍板)第 1 项），`TurnActor` 才变成需要签名的东西。那时再加，加在它该在的位置，而不是提前把它长在每一次调用上。
