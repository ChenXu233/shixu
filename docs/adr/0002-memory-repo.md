# ADR-0002：全部记忆进版本历史，仓库默认私有

> **状态**：`accepted`
> **日期**：2026-10-30
> **落地阶段**：P3
> **上游材料**：[跨场所记忆](../explanation/memory.md)

## 背景

记忆要版本化（可回溯、可审计、可回滚、可迁移），这一点没有争议。争议在**私聊记忆（private 层）要不要进历史**：

- 进 → 私聊内容可能被推到公开仓库、被同步到多台设备；
- 不进 → 「它当时在私聊里知道什么」永远查不到，调试拟人行为失去唯一手段。

## 决策

采用**方案 B：全放 + 私有仓库** —— private 记忆照常入库、照常有版本历史；是否公开、公开时含不含 private，由开发者自己决定；不做加密。

生效的规则表只写在[记忆仓库的公开策略](../reference/policies.md#记忆仓库的公开策略)，本 ADR 只记为什么这样定。

三条推论：

- **记忆的完整性优先于「private 不进历史」** —— private 也有版本历史，才能回溯「它当时在私聊里知道了什么」；
- **风险控制放在权限层，不放在内容层**（谁能 push、谁能看仓库、谁能开公开），而不是把内容藏起来；
- 推送到公开仓库前仍然跑凭据扫描 —— 那是防密钥进仓库，不是防人。

## 被否决的替代

- **方案 A：private 只在本地不版本化** —— 丢掉审计与回溯，且迁移时无法连续。
- **加密存储**：防君子不防小人。钥匙在开发者手里，挡不住他，也解决不了仓库权限泄露的根本问题；复杂度白付。
- **自动排除 private**：替开发者做了本该他做的决定，且让人误以为安全。

## 影响

- 人格工作区是 git 仓库，`private/` 目录与其他层同等对待；
- 控制台必须能看见「哪些记忆在仓库里」，避免用户误判；
- 云端托管（GitHub）是可选动作，默认不自动推送。
