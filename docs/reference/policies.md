> **读者**：实现者（照此写）、评审者（照此判）
> **上游材料**：[权限与身份](../explanation/permission-identity.md)、[沙箱与产物交付](../explanation/sandbox-delivery.md)

规则要么可判，要么不写。本页每条都能落成代码里的一个判断或一张配置表。

## 红线

违反任何一条，实现即作废，不接受「先跑通再补」。

| # | 红线 | 判据 |
|---|---|---|
| 1 | **只有 `dsh-shixu-channel` 实现 `approval/request` 应答者**，driver 不得自己监听 | 全仓搜 `approval/request` 监听，除内核外应为 0 |
| 2 | **记忆写入只有一个入口**（记忆服务），模型不能绕过去直接写文件 | 写入路径只有一处；工具参数无法指定落盘位置 |
| 3 | **身份判定在服务端，与模型说了什么无关**；模型的同意永远不是授权 | 判定只读服务端状态（身份表 + 规则表），不读对话内容 |
| 4 | **未识别者的落点永远拿不到「不可逆 + 高影响」能力**；这个落点删不掉，也不能被配成更高 | 身份表里查不到的 subject 落进默认角色；该角色在代码里硬拦，不读配置 |
| 5 | **每个对外动作必须留凭据**；「可撤回」必须真的可撤回（有快照、能一键回滚） | 动作目录必须声明 `reversible`；`ActionReceipt` 无条件生成 |

## 风险只提供默认值

驱动在 `ActionDescriptor.risk` 里声明原生风险，它换来的只是一个**默认决策**，不是终局：

| risk | 原生默认 |
|---|---|
| read | `allow` |
| write | `allow` |
| destructive | `ask` |

真正生效的是角色矩阵里那一格；没有格就用这张表；连这张表都没有（门 B 的工具）就是 `deny`。矩阵形状见[身份与权限](contracts-persona.md#身份与权限)，决策理由见 [ADR-0007](../adr/0007-rbac-carries-authorization-and-risk.md)。

> DSH 插件不受沙箱保护（以本机权限运行，不在 DSH 工具审批沙箱内）。真正的权限边界是「驱动能调用哪些平台动作」+「这个角色被允许用哪些」，前者由驱动声明，后者由用户配。

**判定三步：**

1. **从后往前**，第一条命中的规则胜出（后面的覆盖前面的）；
2. 一条都没命中 → 上表的原生默认；
3. 原生默认也没有（门 B）→ `deny`。

> **不是「取最严」。** 取最严会让兜底规则吃掉一切：`{ match: '*', decision: 'deny' }` 打底之后，任何 `allow` 都赢不了它 —— 用户永远只能拿到默认拒绝，而角色存在的目的正是「从默认里放开几条」。顺序必须能表达覆盖，否则矩阵只有一半的表达力。

`ask` 落到 `tools/pre-execute` 的闸门 → 推到会话所属聊天里问人；`deny` 直接把理由回给模型，让它换条路。

## 风险判据：可逆性 × 影响半径

不按「读 / 写 / 破坏」分，按**能不能撤回**和**炸多大**分：

| | 影响半径小（仅本场所） | 影响半径大（对外 / 他人 / 你的信用与金钱） |
|---|---|---|
| **可逆**（能撤回、能恢复） | 自动允许 —— 自主回合也可以 | 自动允许 —— 自主回合也可以（但必须留凭据可一键撤销） |
| **不可逆** | 自动允许，留凭据 | **出厂默认：自主时问人；有授权者明确指示时允许。角色矩阵可放开。** |

这张表决定的是 `ActionDescriptor.risk` 该填什么，以及它换来的原生默认；**不是**终局裁定。终局在矩阵里（[ADR-0007](../adr/0007-rbac-carries-authorization-and-risk.md)）。

### 出厂矩阵

矩阵是用户配的，这张是**出厂值**，改它不需要改代码。列是出厂角色 —— 用户可以加自己的角色、改名、删掉不用的；但「未识别者落进的那个角色」必须存在，且它的下限不由配置说了算。

每个角色的规则表**第一行是兜底**（`{ match: '*', decision: 'deny' }`），后面逐条放开。判定从后往前，所以往后加 = 往后放开：

```text
{ match: '*',        decision: 'deny'  }   ← 兜底
{ match: 'qq_*',     decision: 'ask'   }   ← 群里的动作先问一句
{ match: 'qq_recall', decision: 'allow' }  ← 撤回自己发的消息不问
```

`qq_kick` 命中前两条，取最后一条 → `ask`；`qq_recall` 命中三条，取最后一条 → `allow`；`mcp__calendar__create` 只命中兜底 → `deny`。

| 能力 | 自主回合（没人指示） | owner 回合 | guest 回合 |
|---|---|---|---|
| chat（回话、发消息） | ✅ | ✅ | ✅ |
| tools · 可逆（禁言与解除、设撤管理员、自己退出前的准备动作） | ✅ | ✅ | ❌ |
| tools · 不可逆且低影响（改本群设置、删本群消息） | ✅ | ✅ | ❌ |
| tools · 不可逆且高影响（花钱、以你名义承诺、对外不可撤回地泄露私密信息） | ❌ | ✅ | ❌ |
| files（沙箱写文件、跑命令） | ✅ 仅自己的场所目录 | ✅ | ❌ |
| publish（发布站点） | ✅ 可撤回 | ✅ | ❌ |
| admin（改人设、预算、白名单、身份表） | ❌ | ✅ | ❌ |
| memory:public | ✅（自己做的公开事） | ✅ | ❌ |
| memory:core | ✅ | ✅ | ❌ |

涉及信用的六项动作，统一归入「不可逆 + 高影响」：① 花钱（订阅 / 下单 / 充值 / API 额度）② 以你名义做承诺（退款 / 签约 / 替你拍板）③ 把私密内容发到不可撤回的地方（公开网 / 陌生人私聊）④ 删除不可恢复的第三方数据 ⑤ 冒用你的身份对外声称是你做的 ⑥ 改权限 / 白名单 / 身份表。

## 三层同时收紧

缺一层就漏：

| 层 | 手段 | 作用 |
|---|---|---|
| ① 工具暴露 | `agent.ctx` shadow tools + `ctx.tools.restrict(filter)` | guest 面前根本不出现 `qq_kick` / `persona_deploy` |
| ② 执行闸门 | `tools/pre-execute` + `ctx.tools.guard()` + capability 校验 | 即使模型硬调也拦下（fail-closed） |
| ③ 记忆写入 | `persona_remember` 受角色规则限制 | 未识别者不能往 public / core 层写东西 → 防持久化投毒 |

外加沙箱：`files` 能力决定该回合能否写文件 / 起进程。

## 发布安全清单

不能靠提示词自觉，必须由发布服务钉死：

| # | 规则 | 原因 |
|---|---|---|
| 1 | **发布根隔离 + 路径消毒** | slug 走白名单正则；root 必须在 publish root 内；拒绝 `..`、绝对路径、符号链接逃逸 |
| 2 | **默认不公开** | 默认 `visibility = token`（链接 + 随机口令）；`public` 必须走内核的唯一审批应答者，由主人点头 |
| 3 | **发布前凭据扫描** | AI 生成的网页极易把 `.env` / `sk-xxx` / token 写进产物 —— 发布前扫一遍，命中断发布 |
| 4 | **可吊销 + 审计** | 一键下线（停进程 + 删站点）；记录「谁在哪个群要求发布、发到哪」 |
| 5 | **静态优先 + 体积频率上限** | 默认静态托管，不在宿主进程里执行产物脚本；限体积与发布频率 |
| 6 | **插件代码不受沙箱保护** | 沙箱管的是模型工具调用；发布器与插件本身仍以宿主权限运行 |

## 默认参数

实现在没有配置时用这些值。要改就改这里，不要在代码里留魔数。

| 参数 | 默认 | 含义 |
|---|---|---|
| 唤醒条件 | 私聊必醒；群里被 @、被叫到名字时立即醒；其余看下面两条时间线 | 有人聊天不代表在叫它，逐条接话会被当成噪音源 |
| 看场所的节奏 | 刚看过 60 秒内不重复醒；有 2 条以上积压就去看；安静满 30 分钟也去看一眼（人会在群里冒一句「怎么不聊了」） | 两条时间线来自 MaiBot 的防抖与 no_action_backoff：既不能盯着不放，也不能像掉线 |
| 说话总量 | `talkValue`（默认 1，0.3 明显话少）：按 1/talkValue 拉长上面两条时间线，连续沉默再慢 20%／次（封顶 5 次） | MaiBot 的 talk_value 与 backoff；旋钮只影响「多久看一次」，说什么由模型决定 |
| 回复引用 | `never`（默认）不引用；`when-older` 答的不是最新那条时才引用；`always` 每条都引用。私聊一律不引用 | 真人不每句都引用，引用多了像客服系统。这是口味，交给主人定；引擎只提供档位 |
| 打字节奏 | 每条回复前等 `600ms + 字数/8 秒`，抖动 ±15%，单条封顶 6 秒；长回复按句拆，最多 3 条 | 秒回一大段是最明显的机器人信号；连着发五条比一段更烦人 |
| 工具开放面 | 只读动作 + 可逆的写动作 | 不可逆与高影响的一律不开放：审批闸门还没接线，放出去就是让模型替人做决定 |
| 谁用得动 | 只读动作谁都能用；可逆的写动作只给主人和他写进信任表的人 | 群里随便一个人都能让它禁言别人，那就不是助手而是凶器。平台角色不算数：[ADR-0011](../adr/0011-trust-table-is-the-only-authority.md) |
| `attention.cap` | 3 | 同时挂着的场所数上限（可配到 5–8） |
| `rate` | 60 000 ms / 8 条 | 跨所有场所的发言速率（防刷屏） |
| `fairnessMs` | 3 分钟 | 任一在场场所 pending 超时即强制切换注意力 |
| `dampMs` | 90 秒 | 收起场所后的最小重入间隔；被 @、主人指令、群友直接回复时破例 |
| `visit.capReplies` | 8 | 单次进入最多发言条数 |
| `visit.capDwellMs` | 10 分钟 | 单次进入最长停留 |
| `busy.pendingTtl` | 30 分钟 | 忙碌期间积压消息的存活期，过期丢弃不补回 |
| `dailyProactive` | 10 条 | 每日主动发言上限 |
| 发布默认可见性 | `token` | 链接 + 随机口令；公开需主人批准 |
| 梦境 cron | 每天 23:30 | 人格做梦回合的默认触发时间 |

## 记忆提交策略

别每条记忆一个 commit。

| 变更类型 | 提交时机 |
|---|---|
| core / public / 身份表变更 | 立即 commit（高价值，值得一条清晰历史） |
| venue 日常事实 | 批量 commit（按天或按小时） |
| 人设 `persona.md` 修改 | 立即 commit |
| 一次梦境回合结束 | 一个总结性 commit + tag（`dream/YYYY-MM-DD`） |

commit message 结构化，便于读历史：

```text
memory(core): 记住主人不喜欢被主动打扰
venue(qq:12345678): 新增 3 条群事实
dream/2026-10-30: 巩固 12 条，衰减 7 条，提炼 2 条约定
```

## 记忆仓库的公开策略

全部记忆（含 private）都进版本历史，仓库默认私有。

| 项 | 规则 |
|---|---|
| 默认 | 仓库私有；private 记忆照常入库、照常有历史 |
| 要不要公开 | **由开发者自己决定** —— 公开仓库是开发者的选择，不是系统的默认 |
| 公开时 private 放不放 | **由开发者自己决定**；系统不替他决定，也不自动替他排除 |
| 加密 | **不做**。钥匙在开发者手里，挡不住他，也解决不了仓库权限泄露的根本问题 |

决策过程见 [ADR-0002](../adr/0002-memory-repo.md)。
